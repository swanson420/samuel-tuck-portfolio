SLAav

An SLA authority layer for Zendesk-style support teams.

Status: backend MVP, deployed behind an API key. It builds and its full test suite passes. The finance and operations views are API endpoints for now; the screens come next, once the core has proven itself. The source code is private, and a walkthrough is available on request.

When a support SLA is breached, someone pays, and the ticketing platform's own logs can be edited after the fact. SLAav keeps an independent, tamper-evident record of every SLA event. It works out why each breach happened, routes a fix, and gives finance and operations a dollar figure they can defend.

How it works

Append-only ledgerA Postgres ledger with an immutability trigger. Any attempt to edit or delete history is rejected by the database itself.
Keyed hash chainEvery entry is linked to the one before it with HMAC-SHA256. Forging an entry requires the signing key.
Root-cause routingPending State Abuse, Routing Ping-Pong, Triage Delay, Agent Timeout, or System Unavailable
CFO view (API)Active breaches, total financial exposure, and breakdowns by severity and root cause
COO view (API)Operational attribution, time spent in pending, and triage completion
CertificatesPer-ticket cryptographic proof of the ledger's state

How it's verified

  • 193 tests run in CI against a live Postgres database, not mocks.
  • The hash chain is checked independently. A test recomputes each HMAC from scratch and requires an exact match with the stored hash.
  • 14 adversarial ingestion tests. Malformed or hostile data goes to quarantine and is never quietly “fixed up.”
  • Load tested against real production, three times. Database pool use peaked at 90% and 75% under normal settings without tripping the circuit breaker. A third session shrank the pool on purpose to force the breaker open, which confirmed that it degrades gracefully and recovers as designed.
  • Every claim is pinned to a commit and a CI run in an evidence package.

Limits, stated openly

Not yet claimed: a production scheduler, an automated repeatable load-test suite, a key-rotation drill, a Bitcoin-confirmed timestamp anchor, a public third-party proof endpoint, or multi-instance high availability.

“Claims track commits and CI runs, not intent.”
